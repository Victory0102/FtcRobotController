# FTC Run Health — Architecture

## Overview

```
┌─────────────────────────────────────────────────────┐
│              FTC Robot Controller (Java)            │
│                                                     │
│  OpMode ──► RunHealthSession.start(...)             │
│                  │                                  │
│                  │ loop() + capture()               │
│                  ▼                                  │
│           In-Memory Ring Buffer (≤ 5,400/motor)     │
│                  │                                  │
│                  ▼                                  │
│           finish() ─► /FIRST/RunHealth/runs/*.csv   │
│                                                     │
│  @WebHandlerRegistrar ─► RunHealthWeb               │
│                  │                                  │
│                  ▼                                  │
│           RunHealthApi  ─► JSON / CSV / HTML        │
│                                                     │
└─────────────────────────────────────────────────────┘
                          ▲
                          │ HTTP (Control Hub Wi-Fi)
                          ▼
┌─────────────────────────────────────────────────────┐
│               Browser Viewer (TypeScript)           │
│                                                     │
│  parser.ts, metrics.ts, comparison.ts               │
│  standalone.ts (drag-drop) │ controlhub/api.ts      │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## Robot-side package map

All robot-side code lives under
`TeamCode/src/main/java/org/firstinspires/ftc/teamcode/runhealth/` with
the subpackages:

| Package | Role |
|---------|------|
| `logging` | Logger session, CSV codec, run IDs, filename sanitizer, motor discovery, battery reader, recording-mode store, file storage. |
| `api` | Pure HTTP-style API and the SDK-facing `@WebHandlerRegistrar` shim. |
| `examples` | Disabled `ExampleLinearOpMode` and `ExampleIterativeOpMode`. |

Sample-data fixtures live in `sample-data/` at the repository root.  They're
generated by `sample-data/scripts/generate.js` for deterministic tests.

## Frontend map

All frontend code lives in `viewer/`:

```
viewer/
├── package.json
├── tsconfig.json
```

## Control Hub hosting

`viewer/` builds JavaScript + CSS that is copied (via `npm run build`) into
`TeamCode/src/main/assets/runhealth/`.  The `@WebHandlerRegistrar`-driven
`RunHealthWeb` registers a dispatching handler with the Robot Controller's
WebHandlerManager under several `/runhealth/` routes.  Each registered route
returns either the bundled UI or, for `/runhealth/api/*`, JSON.

When the bundled UI is unavailable (a team has not yet run `npm run build`),
the `/runhealth/index.html` route returns a small fallback HTML page that
links to `/api/runs` so the team can verify the API is reachable.

## Bundled dependency footprint

The robot-side code adds **no third-party dependencies**.  All API and
parsing logic is implemented in plain Java so the SDK compiles
unchanged.  The viewer likewise depends only on dev-time tools
(`typescript`, `vitest`).

## Failure model

Every logger and API entry point is defensively coded:

* `RunHealthSession.capture()` never throws; per-motor read failures are
  isolated, the buffer continues.
* `RunHealthSession.finish()` is idempotent and never throws.
* `RunHealthApi.handle()` returns structured JSON errors with HTTP status
  codes; it never returns stack traces to callers.
* `RunHealthWeb.registerRunHealthRoutes(...)` swallows registration
  failure so a competing version of `WebHandlerManager` cannot stop the
  OpMode.

See `SECURITY.md`, `LIMITATIONS.md`, and `CONTROL_HUB_TEST_PLAN.md` for
additional guarantees and known gaps.

## Live telemetry

The Live tab is a read-only browser dashboard over the bounded
`LiveSnapshotRegistry`.  `RunHealthSession.capture()` publishes the
latest immutable `LiveSnapshot` (one reachable object, never a
queue) under the session lock.  `finish()` calls
`LiveSnapshotRegistry.markInactive()` so the browser sees
`active=false` while preserving the last field values.  The
`GET /runhealth/api/live/snapshot` endpoint is GET-only by
construction; see `LIVE_VIEW.md` for the schema, polling cadence,
and bounded browser buffers.
